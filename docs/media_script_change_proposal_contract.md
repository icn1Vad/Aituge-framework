# Media Script Change Proposal Contract

## Status

This document freezes the phase-1 contract. The task is registered for discovery, but its Pipeline and Skill are implemented in the next phase. Clients must not start this task until `media-script-change-proposal-v1` is registered.

## Boundary

The feature uses explicit user intent. The client selects one of two routes:

```text
ask_detail     -> media.chat
propose_change -> media.script.change.propose
```

TaskManager does not ask an Agent to classify the route. A proposal is advisory until a user confirms it. Confirmation creates a new script run and never overwrites the source script or Artifact.

No Scheduler, Single Agent, ReAct, Conversation, ToolManager, or SkillManager internals are changed.

## Proposal Task

```text
task_type: media.script.change.propose
handler: pipeline
pipeline_id: media-script-change-proposal-v1
agent: default-single-agent
skill_package: media-script-change-proposal-package
primary_skill: media-script-change-proposal
tools: []
datasets: []
```

The future Pipeline is:

```text
context -> propose -> await_confirmation
```

## Input Fields

| Field | Required | Meaning |
|---|---:|---|
| `message` | yes | User's requested change. |
| `base_script_id` | yes | Immutable source script identifier. |
| `base_artifact_id` | no | Source TaskManager Artifact identifier. |
| `conversation_thread_id` | no | Script-scoped chat thread. |
| `recent_messages` | no | Bounded recent conversation context. |
| `current_script` | no | Current readable and structured script data. |
| `topic_card` | no | Selected topic context. |
| `persona` | no | Current persona context. |
| `user_constraints` | no | Duration, platform, and explicit preservation constraints. |

## Proposal Output

Agent output has only two statuses:

- `pending_confirmation`: contains at least one target field and actionable change.
- `needs_clarification`: contains a non-empty clarification question.

`approved`, `rejected`, and `applied` are runtime lifecycle states. They are never generated by the Agent.

| Field | Meaning |
|---|---|
| `summary` | Human-readable proposal summary. |
| `reason` | Why the requested changes help. |
| `target_fields` | Script fields allowed to change. |
| `changes` | Field-level change instructions. |
| `preserve_fields` | Fields that must remain unchanged. |
| `storyboard_regeneration_required` | Whether the storyboard must be regenerated. |
| `warnings` | Risks or limitations for confirmation. |
| `clarification_question` | Required only when clarification is needed. |

## Revision Input

`media_script_generate_input` remains backward compatible. When `revision_mode=false`, existing generation payloads remain valid. When `revision_mode=true`, these fields are required:

```text
base_script_id
proposal_artifact_id
previous_script
change_proposal
```

Optional lineage fields include `base_artifact_id` and `parent_task_id`. `preserve_fields` constrains the future Writer stage. The task-level parent relationship remains authoritative when both task metadata and payload contain a parent id.

## Phase-1 Non-goals

- No Proposal Pipeline implementation.
- No Proposal Skill content.
- No human-review pause/resume wiring.
- No revision Writer execution.
- No 8010 bridge or frontend control.
- No changes to the known long-answer rendering issue.
