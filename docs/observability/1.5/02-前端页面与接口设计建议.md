# 管理员观测平台：前端页面与接口设计建议

版本：1.5  
目标：前端可以立即开始信息架构、页面和组件设计；后端按统一接口逐步接入真实数据源。  
访问边界：浏览器只调用 Java `/monitor/observability`，不直连 Python、数据库、Loki、Tempo 或 Prometheus。

## 1. 建议设计页数

建议设计 **8 个一级页面**，另做 **3 个复用详情组件**。这样既覆盖全部日志与观测信息，又避免每个业务功能单独做页面。

| 编号 | 一级页面 | 核心目的 | 当前可用性 |
|---|---|---|---|
| P1 | 观测总览 | 全局健康、任务、模型、安全和错误摘要 | `[已确定待开发]` |
| P2 | 统一事件中心 | 按时间和关联 ID 查询所有事件元数据 | `[已确定待开发]` |
| P3 | 业务任务中心 | 查询合同、问答、知识库、Proof 等任务和时间线 | 部分数据 `[现有]`，聚合接口待开发 |
| P4 | 模型调用分析 | 调用量、成功率、Token、耗时、模型/模式分布 | `[已确定待开发]` |
| P5 | 安全审计 | 权限、跨租户、导出、私密模式和配置变更 | `[已确定待开发]` |
| P6 | 运行日志 | 集中查询各容器 ERROR/WARN 和上下文 | 依赖 `[规划]` Loki |
| P7 | 调用链追踪 | 查看 Java→Python→Worker→模型→回调瀑布图 | 依赖 `[规划]` Tempo |
| P8 | 服务健康与告警 | 服务、Worker、队列、数据库、容量、告警、留存 | 依赖 `[规划]` Prometheus |

复用组件：

1. D1 事件详情抽屉；
2. D2 任务/Run 时间线详情页或全屏抽屉；
3. D3 异步导出任务弹窗。

前端可以先设计全部 8 页，但后端实现先做 P3 单任务详情和统一时间线，再做列表、模型和安全查询，最后才做依赖统计口径的 P1 总览。P6–P8 使用明确的“数据源未接入”空状态，不制造假数据为已上线能力。

## 2. 全局框架

### 2.1 全局筛选条

所有页面复用以下筛选：

- 环境：只读显示，由当前域名/部署实例决定；切换环境实际跳转到另一个管理端 Origin 并重新认证，不能通过查询参数切换；
- 时间：默认最近 24 小时，快捷 15 分钟、1 小时、24 小时、7 天、10 天；
- 租户：租户管理员不显示选择器；超级管理员使用 `CURRENT`、`SELECTED`、`ALL`，选择跨租户范围时必须填写查询原因；
- 服务/业务域/功能；
- `requestId`、`traceId`、`taskId`、`runId`、`reviewId`；
- 结果：成功、失败、拒绝、取消、超时、部分完成；
- 刷新：手动、10 秒、30 秒、关闭。

超级管理员首次选择“选择租户”或“全部租户”时，前端要求原因码和工单/事件编号，通过 `X-Observability-Access-Reason` 新建 Access Session；同 Scope、权限和筛选的自动刷新复用 `X-Observability-Access-Session`。Session 不能扩大范围。列表返回的 `accessContext` 用于详情，后端仍检查目标租户属于原范围。

### 2.2 通用状态

页面必须区分：

- 无结果：查询成功但没有数据；
- 数据源未接入：例如 Loki 尚未部署；
- 部分数据：某个上游超时，其他卡片仍可展示；
- 无权限；
- 请求失败；
- 数据延迟。

不得把“数据源未接入”显示成“系统一切正常”。

### 2.3 信息展示底线

默认展示元数据，不显示：

- 密钥、Authorization、Cookie、密码；
- 合同全文和文件内容；
- 完整 Prompt、模型回答、Tool 参数；
- 未脱敏个人信息。

详情返回 `sensitivity` 和 `redactions`，前端用“已脱敏”标签说明，不提供通过浏览器参数绕过脱敏的能力。

## 3. 页面设计

### P1 观测总览

建议区块：

1. 服务健康：正常、异常、未知、数据时间；
2. 业务执行：任务数、成功率、失败数、平均/P95 时长；
3. 模型调用：调用量、成功率、Token、P95、外部/本地模型占比；
4. 安全事件：拒绝、跨租户、敏感导出、配置变更；
5. TOP 错误码和受影响功能；
6. 任务队列与 Worker；
7. 最近告警；
8. 数据源状态：DB、Loki、Tempo、Prometheus。

交互：

- 点击卡片跳至相应页面并带入当前筛选；
- 总览默认缓存 15–30 秒；
- 每个数字显示统计时间窗和最后更新时间。

接口：

```http
GET /monitor/observability/overview
```

### P2 统一事件中心

用途：不要求管理员预先知道信息在哪张表，通过统一格式查询 HTTP 管理审计、业务事件、任务事件和模型生命周期事件。`UnifiedEvent.source` 只能是 `HTTP_AUDIT/BUSINESS_EVENT/TASK_EVENT/MODEL_EVENT`，DTO 不包含 `runtimeMessage`。安全事件和运行日志都不进入统一事件中心，分别从具有 `security`、`runtime` 权限的专用页面查询。

列表列：

- 时间、级别、分类、事件名称；
- 服务、业务域、租户；
- 业务对象；
- taskId/runId/traceId；
- 结果、错误码、耗时；
- 详情。

筛选增加：

- `source`：`HTTP_AUDIT`、`BUSINESS_EVENT`、`TASK_EVENT`、`MODEL_EVENT`；
- `category`、`eventName`、`level`、`errorCode`、`privacyMode`、`routeType`、`modelPackId`。

接口：

```http
GET /monitor/observability/events
GET /monitor/observability/events/{source}/{eventId}
```

后端不建议用跨库 SQL 强行 UNION。由 Java 对各数据源做有界查询并按 `occurred_at DESC, source_order DESC, event_id DESC` 归并。第一页冻结 `snapshotTo` 和每个来源的摄取高水位/PIT。任一来源超时时，前端可展示“本页不完整”预览，但必须禁用“下一页”，只允许使用 `retryToken` 重试当前页。

### P3 业务任务中心

用途：以 task/run 为主线查看合同审查、智能问答、知识库处理、Proof 和后续任务。

列表列：

- 功能、任务类型、任务 ID；
- 业务对象、租户、发起人；
- 当前状态、阶段、进度；
- 创建/开始/结束时间、总耗时；
- 模型模式、错误码、重试次数。

D2 时间线展示：

```text
Java 创建任务
  → Python 接收
  → Run 创建
  → Stage/Tool/Agent
  → 模型调用
  → 回调 Java
  → 业务终态
```

每个节点显示来源、时间、耗时、结果、错误码和关联 ID。元数据不完整时显示“未采集”，不能猜测。

Task 跨租户列表中的 `tenantId` 是必填契约字段；缺失时视为协议错误，不能继续详情跳转或由前端猜测租户。

时间线采用分页加载；默认先显示关键节点，再逐页展开完整事件。禁止 Java 为一次页面请求循环拉完全部内部事件，也禁止静默截断。

接口：

```http
GET /monitor/observability/tasks
GET /monitor/observability/tasks/{taskId}
GET /monitor/observability/tasks/{taskId}/timeline?cursor=...&retryToken=...&limit=...
GET /monitor/observability/runs/{runId}/stages
GET /monitor/observability/runs/{runId}/events
GET /monitor/observability/runs/{runId}/events/stream
```

一期仅对单个正在运行的 Run 使用 SSE；全局列表仍用轮询。前端使用 `fetch()` + `ReadableStream` 携带 Bearer Header，不使用原生 `EventSource`。SSE `id:` 就是 `eventId`，`data.sequence` 是顺序号；断线时把最后一个 eventId 放入 `Last-Event-ID`。收到 409 `EVENT_STREAM_REPLAY_GAP` 时先用分页事件补齐；收到 410 `EVENT_STREAM_RESET_REQUIRED` 或 `reset-required` 事件时丢弃恢复游标并从分页接口重建状态，不能无限重连。

### P4 模型调用分析

统计：

- logical call、调度尝试、已确认实际请求、未调度和调度未知数量，以及各自成功/重试口径；
- 输入/输出 Token；成本按币种分别展示，禁止把 CNY 与 USD 直接相加；
- 平均/P50/P95/P99、首 Token 时长；
- 模型、模型包、提供方、本地/外部、私密模式；
- 功能、Stage、错误码；
- 时间趋势。

模型调用列表严格“一行一个模型调度 invocation”，不能把 STARTED 和终态显示成两次调用。只有 `dispatchStatus=DISPATCHED` 计入已确认实际模型请求；`DISPATCH_UNKNOWN` 必须单列，`NOT_DISPATCHED` 不计 Provider 调用、成本或模型重试。输入 Guardrail、凭据缺失和路由拒绝不创建 invocation。跨租户列表中的 `tenantId` 和 `featureCode` 是必填字段。点击详情后显示追加式生命周期事件。

- `logicalCallId`：一次业务模型调用；
- `invocationId`：一次进入模型调度边界的尝试；
- `dispatchStatus`：`NOT_DISPATCHED | DISPATCHED | DISPATCH_UNKNOWN`；
- `lifecycleStatus`：`RUNNING` 或 `TERMINAL`；RUNNING 时 `outcome=null`；
- 业务调用量与实际请求量；
- 逻辑调用成功率与尝试成功率；
- `privacyMode=STANDARD|PRIVATE`；
- `routeType=LOCAL|EXTERNAL`。

凭据只展示无业务含义的模型配置 ID，不展示普通哈希。

摘要必须由 Python/数据库投影侧聚合，支持 P50/P95/P99、TTFT、时间趋势、错误码、provider、model、routeType 和 privacyMode 分布；Java 不得拉取全量事件现场计算。

接口：

```http
GET /monitor/observability/model-summary
GET /monitor/observability/model-invocations
GET /monitor/observability/model-invocations/{invocationId}
```

### P5 安全审计

筛选：

- 分类：认证、授权、租户、数据访问、导出、私密模式、模型配置、权限配置、发布；
- 风险：低、中、高、严重；
- 动作、结果、操作者、主体、IP 摘要；
- 是否跨租户。

列表/详情：

- 谁、何时、从哪里、对什么对象、执行什么动作；
- 成功/失败/拒绝及原因码；
- requestId、traceId；
- 已脱敏元数据；
- 审计记录本身的查看/导出历史。

专用页面使用严格的 `SecurityEvent`，不复用字段大多可空的统一事件 DTO。系统级拒绝允许 `scopeType=SYSTEM`、`tenantId=null`，操作者可为 `ANONYMOUS` 或 `UNKNOWN`；租户、操作者或主体缺失时必须显示服务端给出的 `missingContextReason`，不能渲染空对象冒充完整上下文。

接口：

```http
GET /monitor/observability/security-events
GET /monitor/observability/security-events/{eventId}
```

进入页面需要 `monitor:observability:security`。统一事件中心不能绕过该权限。跨租户列表首次授权创建 Access Session 和一个 `auditActionId`；10 秒自动刷新复用 Session，不重复生成逻辑安全行为。敏感详情、导出、配置/权限修改和边界拒绝仍单独审计。一次 Java 查询产生的多层事件按 `auditActionId` 去重。

### P6 运行日志

依赖 Loki。页面能力：

- 服务、容器、级别、logger、错误码；
- 关键词和关联 ID；
- 前后文展开；
- 聚合错误模板和趋势；
- 固定时间窗分享链接，但链接不得包含敏感查询值。

接口：

```http
POST /monitor/observability/runtime-logs/search
POST /monitor/observability/runtime-logs/detail
```

Java 将安全筛选转换为 Loki 查询，禁止前端直接传任意 LogQL。页面和接口要求 `monitor:observability:runtime`。关键词放在 POST Body，避免进入代理日志和浏览器历史。专用页面使用 `RuntimeLogEntry`，结构化显示 container、logger、stream、exceptionType 和已双重脱敏的 message。`locator` 是 Java 签名的短期 opaque locator，不是 Loki 原生日志 ID；前端同时显示 `locatorExpiresAt`，过期后重新查询而不是持久化 locator。

### P7 调用链追踪

依赖 OpenTelemetry + Tempo。

页面：

- Trace 列表：入口、服务数、总耗时、结果；
- 瀑布图：Java、Framework、队列等待、Worker、模型、工具、回调；
- Span 详情：名称、服务、开始时间、耗时、状态、受限属性；
- 关键路径和错误 Span。

当前契约允许展示尚未结束、`status=UNSET` 的 Trace，因此 Trace 列表属于可变投影，首次查询使用物化结果集；如果以后改为只返回已结束 Trace，方可改用追加式高水位。

接口：

```http
GET /monitor/observability/traces
GET /monitor/observability/traces/{traceId}
GET /monitor/observability/timeline?taskId=...&cursor=...&retryToken=...&limit=...
```

前端不展示 Span request/response body。

### P8 服务健康与告警

依赖 Prometheus/Alertmanager，部分部署信息可来自 Docker/发布系统。整个页面要求 `monitor:observability:operations`，租户管理员默认不可见；总览中的系统级卡片也按此权限裁剪。

区块：

- 服务实例、版本、健康检查、最近部署；
- Worker 数量、租约和积压；
- 数据库/Redis/队列；
- CPU、内存、磁盘和连接池；
- 当前告警和历史告警；告警确认/静默不在本期范围，若后续需要必须单独定义写接口和安全审计；
- 各数据源留存、已用容量、最老/最新数据；
- 当前实例的环境标识和隔离配置状态；不跨环境探测另一套系统。

Alert 的 `FIRING/RESOLVED` 和 `resolvedAt` 会更新，告警列表必须物化首次返回摘要，不能在后续页重新查询当前状态。

接口：

```http
GET /monitor/observability/services
GET /monitor/observability/alerts
GET /monitor/observability/storage
```

### 4.3 查询限制

- 默认最近 24 小时；
- 普通交互查询最多 30 天；
- `limit` 默认 50，最大 100；
- 游标不透明且有时效，绑定服务端高水位/PIT 或可变投影结果清单、筛选、用户、权限和租户范围；底层 PIT Token 不返回浏览器；
- 所有会 UPDATE 且参与分页或状态筛选的资源使用 `MATERIALIZED_RESULT_SET`：Task、模型 invocation、Alert，以及包含运行中 Trace 的 Trace 列表。服务端冻结固定排序后的 ID、`projectionVersion`、`dataAsOf` 和返回摘要；交互快照默认保留 15 分钟、最多 10,000 条，过期后前端要求从第一页重新查询；
- 列表行代表 `snapshotTo` 时刻的冻结摘要，Task、模型 invocation 和 Trace 详情默认返回最新投影。前端比较列表与详情的 `projectionVersion`；不一致时显示“状态已更新”，以详情的 `dataAsOf` 标明更新时间。本期不提供历史 as-of 详情；
- 同一用户在同一环境默认最多 5 个活跃交互快照；相同 Scope、权限、筛选和时间窗在 30 秒内复用。前端 10 秒自动刷新不得主动制造并保留无界快照；容量超限显示稳定错误码 `OBSERVABILITY_SNAPSHOT_CAPACITY_EXCEEDED`；
- 所有列表和时间线均提供 `retryToken` 提交入口；`cursor` 与 `retryToken` 互斥；
- 只要一个选定来源超时，`complete=false`、`nextCursor=null`、`hasMore=null`，前端只能用 `retryToken` 重试本页；
- 时间范围大、数据超过 10,000 条或生成文件时走异步导出；
- 后端为各数据源设置独立超时，部分失败返回 200 + `sourceStatus.partial=true`；
- 列表范围参数违规返回 403；详情资源不存在或无权查看统一返回 404，内部记录拒绝事件，防止跨租户枚举。
- 所有跨租户 GET/POST 请求统一发送 `X-Observability-Access-Reason` Header；POST Body 只承载筛选条件。前端不得同时在 Header、URL 或 Body 重复原因字段。

固定排序：

| 列表 | 排序 |
|---|---|
| Task | `createdAt DESC, taskId DESC` |
| Model Invocation | `startedAt DESC, invocationId DESC` |
| Security | `occurredAt DESC, eventId DESC` |
| Runtime Log | `occurredAt DESC, sourceTieBreaker DESC` |
| Trace | `startedAt DESC, traceId DESC` |
| Alert | `startedAt DESC, alertId DESC` |
| Task Timeline | `sequence ASC, eventId ASC` |
| Run Event | `sequence ASC, eventId ASC` |
| Correlation Timeline | `occurredAt ASC, sourceOrder ASC, eventId ASC` |

### 4.4 异步导出

```http
POST /monitor/observability/exports
GET  /monitor/observability/exports/{exportId}
GET  /monitor/observability/exports/{exportId}/download
```

规则：

- 只允许导出查询者有权查看的元数据；`export` 必须叠加目标资源原权限和跨租户权限，不会提升可见范围；
- 默认 CSV，必要时 JSONL；
- `POST` 支持 `Idempotency-Key`，浏览器重试不得重复创建相同任务；
- Java 在返回 `202` 前持久化 `querySnapshotId`、`snapshotTo`、各来源内部高水位/PIT、`filterHash`、授权租户范围、目标资源权限和数据/Schema 版本；Worker 只能按该快照执行，10:00 创建的任务不会因 10:05 执行而改变数据边界；
- 筛选条件按 EVENTS、TASKS、MODEL_INVOCATIONS、SECURITY_EVENTS、RUNTIME_LOGS、TRACES、ALERTS 使用不同的严格 DTO；OpenAPI discriminator 必须为七个 `filterType` 提供明确 mapping，未知字段或 `resource/filterType` 不一致返回 400；
- 下载先由 Java 校验用户、租户、创建者、权限和有效期，再记录安全审计并流式返回文件；如使用一次性 302，仍由 Java 完成上述检查；
- 查询导出状态和下载时都重新校验 `export + 目标资源原权限 + 当前租户范围 + 创建者/获准下载者`，不能只在创建时校验一次；
- 创建、完成、实际下载、过期均写安全审计；
- 导出任务不在浏览器内存中拼装。

### 4.5 权限矩阵

| 资源 | 基础权限 | 说明 |
|---|---|---|
| HTTP/业务/任务/模型事件列表 | `monitor:observability:view` | 不包含安全事件和运行日志 |
| 任务、模型、Trace 详情 | `monitor:observability:detail` | 跨租户还需 Access Context |
| 安全事件 | `monitor:observability:security` | 不可从统一事件绕过 |
| 运行日志 | `monitor:observability:runtime` | 详情再叠加 `detail` |
| 服务、告警、存储、系统总览卡片 | `monitor:observability:operations` | 租户管理员默认不可见 |
| 导出 | `monitor:observability:export` + 原资源权限 | 跨租户再叠加 `cross-tenant` |

前端隐藏无权限入口只用于体验，Java 必须逐请求执行相同规则。

## 5. 前后端职责

### 前端

- 组织筛选、页面和可视化；
- 不自行判断租户权限；
- 不构造 LogQL/PromQL/TraceQL；
- 不缓存敏感详情或能力型 Token 到 localStorage/sessionStorage；
- `cursor`、`retryToken`、locator、Access Context/Session 只保存在内存中，不进入历史、埋点、错误上报或分享链接；
- 跨租户 Access Session 用于同 Scope 自动刷新，Access Context 用于详情；过期后回到列表重新授权；
- 清晰展示数据来源、时窗、部分失败和更新时间；
- 所有 ID 可复制，跨页面跳转保留安全筛选。

### Java 后端

- 用户认证、资源权限矩阵、租户范围、Access Context 和跨租户审计；
- 参数白名单、查询范围和速率限制；
- 聚合 Java DB、Python 内部 API、Loki、Tempo、Prometheus；
- 统一 DTO、错误码、事件注册表、脱敏、快照和签名游标；
- 各来源摄取高水位/PIT、超时重试 Token、熔断、缓存和部分结果；
- 异步导出。

### Python 内部接口

- 只接受 Java 服务身份，不信任浏览器角色头；
- 使用服务身份认证，强制执行 Java 下传并签名的环境、租户范围、有效期和唯一请求标识；
- 通过任务、模型、安全专用 DTO 返回完整的结构化受限字段，并提供模型投影聚合；
- 只有跨租户、敏感详情、导出和边界拒绝记录安全审计；普通本租户元数据轮询不产生安全事件。
