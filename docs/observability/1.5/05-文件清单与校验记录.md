## 关键语义检查

- 外部 `UnifiedEventSource` 仅包含 `HTTP_AUDIT`、`BUSINESS_EVENT`、`TASK_EVENT`、`MODEL_EVENT`。
- `UnifiedEvent.source` 直接引用该收窄枚举，外部 Schema 不再存在宽泛 `EventSource` 或 `runtimeMessage`。
- 外部模型列表使用 `ModelInvocationListResponse`，一行一个调度 invocation；实际请求只统计 `dispatchStatus=DISPATCHED`。
- 外部 Access Context 共用于事件、任务、Run、模型、日志、Trace 等详情入口，并绑定原查询范围而非单个资源租户。
- 内部必需的 11 条新增 Path 均存在，外部 Python 数据能力均有明确来源。
- 外部全部分页 GET 与运行日志 POST 均有 `retryToken` 输入；不完整页 `hasMore=null`。
- 追加式来源使用摄取高水位/PIT；Task、invocation、Alert 及含运行中 Trace 的可变列表使用物化结果清单。
- 浏览器响应不包含数据源 `pointInTimeToken`、`opaqueToken`、sequence/eventId 高水位；Java—Python 查询也只传 `hwm_...` 短句柄，原生 PIT 与签名上下文只留在服务端状态。
- 内外模型 DTO 均区分 RUNNING 和 UNKNOWN 终态；内外安全 DTO 均能表达 SYSTEM、匿名和缺失上下文。
- Task、Run 与跨来源关联时间线均分页并具有确定性升序；安全和运行日志使用专用严格 DTO。
- 导出请求使用 7 类专用筛选 DTO，导出任务携带冻结快照元数据，创建、状态和下载均叠加原资源权限。
- Export discriminator 的七个 mapping 均可解析；Task/Model 的跨租户 tenantId 为 required。
- SSE 示例、外部说明和内部说明统一为 eventId + sequence；不存在 `seq`，并具有 409/410/reset-required 恢复协议。
- Task、Invocation、Security、Runtime、Trace、Alert 及三个分页时间线均有确定性固定排序。
- 内外查询快照均返回 `expiresAt`；快照容量超限稳定返回 `OBSERVABILITY_SNAPSHOT_CAPACITY_EXCEEDED`。
- 外部 Runtime、Operations、Security 和 Export 资源组合权限已写入契约。
- 模型 outcome 枚举只使用 `UNKNOWN`，生命周期事件枚举保留 `MODEL_INVOCATION_OUTCOME_UNKNOWN`，两者映射已固定。
- Task、Model、Trace 列表/详情 DTO 返回 `projectionVersion/dataAsOf`；详情接口标记 `x-detail-consistency: LATEST`，不声称提供 as-of 详情。
