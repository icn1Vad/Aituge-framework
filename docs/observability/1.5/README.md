# 日志与管理员观测平台

当前基线版本：1.5。

本目录是 Java、Python 与平台基础设施的日志和管理员观测能力的长期基线。后续功能应先按本目录的路由规则接入既有事件表和观测存储；除非满足明确的例外条件，不为单个业务功能新建专属“日志表”。

## 状态标记

- `[现有]`：源码或环境中已存在并已核对。
- `[已本地修改未推送]`：仅存在于本地开发分支，未进入远程分支和环境。
- `[已确定待开发]`：方案已经确定，可进入工程实现，但当前不能声称可用。
- `[规划]`：基础设施或后续阶段能力，实施前仍需完成部署与验收。

## 使用原则

1. 总体规则以 `01` 为准，接口与页面以 `02`、`04` 为准。
2. 新功能立项或开发前必须填写 `03`，评审时逐项确认。
3. 新功能如果只需要记录事件，不得以“方便查询”为由单独建日志表。
4. 文档中的“待开发”和“规划”不是已上线能力，验收报告必须据实说明。
5. 1.3 基线新增 retryToken 回传闭环、可变投影物化快照、模型运行中状态、SYSTEM 安全事件、时间线分页、专用安全/运行日志 DTO，以及创建时冻结的异步导出快照。
6. 1.4 基线补齐 Export discriminator mapping，彻底收窄 UnifiedEvent，固定跨租户 tenantId、SSE eventId/sequence 语义，并将 Alert、运行中 Trace 等所有可变分页资源纳入有容量上限的物化快照与固定排序。
7. 1.5 基线统一未知终态为 `outcome=UNKNOWN`，补齐三个分页时间线的固定排序，明确冻结列表与实时详情语义，统一跨租户原因 Header，并将 Java—Python 高水位限制为短期 `hwm_...` 服务端句柄。
8. 1.5 总体基线已经冻结；模型调度边界、审计去重、能力型 Token、SSE 恢复、DDL 与契约测试等实现事项统一进入 `07`，不再反复扩写总体基线。
